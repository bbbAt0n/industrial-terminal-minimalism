# Progressive task with preserved context

**Problem:** A task has enough complexity or dependency that showing every control at once obscures the current decision.

**Why it belongs:** Clear hierarchy, restrained disclosure, concise labels, and explicit state provide an engineered feel without simulating a command line. Local feedback and precise grouping preserve orientation.

**Appropriate:** Unfamiliar or dependent decisions, mobile tasks with limited space, consequential operations needing review, or optional advanced controls.

**Avoid:** Splitting a quick expert task into needless steps, hiding important consequences, forcing artificial progress counts, or losing data/context on back navigation.

**Acceptable variations:** Inline disclosure, staged views, expandable advanced settings, or a review step. The number/order follows real dependencies. Keep current state, recovery, and navigation understandable. A task can remain single-screen when that is more efficient.

**Annotated decision:** A mobile report may reveal dependent details after the relevant choice while keeping entered work and a route back. A desktop expert can require those same details visible together for comparison. The shared identity does not force the same disclosure model.
