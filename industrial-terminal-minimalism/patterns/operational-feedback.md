# Operational feedback and discrete activity

**Problem:** An action changes state or takes time, and users need timely, truthful feedback with a recovery path.

**Why it belongs:** Concise state text, restrained ASCII companions, semantic progress, and short stepped emphasis express terminal character through actual operation. Neutral success and meaningful error/connection colors keep the palette quiet.

**Appropriate:** Saving, checking, importing, connecting, cancellation, or another actual operation with observable states. Explicitly identified local simulation is appropriate in an evaluation/prototype that requests it.

**Avoid:** Fake percent completion, ambient activity that implies nonexistent work, decorative command output, excessive live announcements, or loading effects that block unrelated controls.

**Acceptable variations:** Immediate stable text for a fast action; determinate progress from known work; indeterminate state when the total is unknown; state-reactive ASCII as a companion; pause/stop for longer decorative motion. Completion/error/cancellation settle immediately and preserve context. Reduced motion keeps status/progress meaningful without decoration.

**Annotated decision:** A naming tool can illustrate actual character substitutions between source and proposed names while its progress counts only committed changes. Caption the illustration truthfully before commitment; stop old frames when the item changes. Another task may need only immediate text or measured progress. If totals are unavailable, state that the operation is running instead of inventing percentages. Verify readability, interruption, cadence and input response using [motion QA](../execution/motion-qa.md).
