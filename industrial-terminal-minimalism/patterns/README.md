# Curated design patterns

These curated patterns are approved decision resources, not page templates. Choose one only when its problem applies. Do not assemble all of them into every product. A pattern can inform many compositions; the product's intent remains authoritative within the shared DNA.

| Pattern | Use when |
| --- | --- |
| [Typographic introduction](typographic-introduction.md) | Purpose/value and the next decision need clear hierarchy |
| [Ruled information group](ruled-information-group.md) | Related content needs readable grouping or comparison |
| [Bounded selection](bounded-selection.md) | Users must perceive a current item or option |
| [Progressive task](progressive-task.md) | Task complexity benefits from disclosure with preserved context |
| [Operational feedback](operational-feedback.md) | An action changes state or takes time |
| [Character-based explanation](character-story.md) | A product relationship or transformation deserves a composed visual |

Each pattern explains its problem, identity rationale, applicability, exclusions, acceptable variation, and an annotated decision. Reuse the reasoning and interaction contract, not a fixed region count or placement. Review the actual result using [the rubric](../validation/rubric.md).
