# Delivery checklist

Use on the changed scope with evidence and pass / needs correction / unverified / reasoned not applicable. This supports [visual QA](visual-qa.md) and does not replace [the critique rubric](../validation/rubric.md).

- [ ] Product purpose, audience, content, journeys, platform/input modes, and implementation constraints established proportionately.
- [ ] Design intent explains priority, grouping/navigation, typography roles, density, negative space, responsive transformations, and motion choices.
- [ ] Existing architecture/behavior/dependencies preserved; new abstractions/dependencies have a concrete reason.
- [ ] DNA remains recognizable in light and dark without a borrowed universal composition or fabricated content.
- [ ] Typography roles are cohesive across repeated elements, states, themes, and sizes; actual/fallback fonts and long/localized content inspected.
- [ ] All nine visual critique dimensions have observations and evidence; visible material defects corrected.
- [ ] Main journey, recovery, relevant states, keyboard/pointer/touch, and focus/selection/dismissal behavior exercised.
- [ ] Responsive priority, reading order, grouping, navigation, and controls verified at relevant sizes; no-overflow alone is insufficient.
- [ ] Relevant semantic, composed-contrast, target-size, text-scaling/zoom, forced-color, and screen-reader checks completed or explicitly unverified.
- [ ] Motion & ASCII Opportunity Assessment informs the substantial design; multiple artistic/atmospheric/functional concepts considered, with a selected appearance, grid/density/depth, frame behavior and lifecycle. Character graphics earn their scale in this product.
- [ ] Ambient/reactive/interaction motion inspected at normal speed with actual intermediate/boundary frames; user pause, meaningful static alternatives, dynamic reduced preferences, truthful data and zero inactive animation schedulers checked.
- [ ] Active frame cost, input independence and a representative lower-performance condition checked or explicitly unverified; buffers and lifecycle ownership remain bounded.
- [ ] Relevant project/token checks run; final screenshots/temporal observations refreshed after corrections.
- [ ] Delivery distinguishes technical checks, inspected visual results, actual interactions/motion, and unavailable/manual verification.
