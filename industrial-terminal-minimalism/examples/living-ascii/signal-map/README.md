# Signal map / APPROVED, SCOPED Braille, Amber Glow and Old Monitor

Open `index.html` directly in an existing browser, offline. No server, external assets, fonts, library or WebGL2 is required. `?mode=amber&theme=dark` selects Amber Glow and dark UI; `?mode=monitor&theme=light` shows default green Old Monitor in light UI; add `&phosphor=warm`, `cool`, `green` or an opaque hex value to select its colour; buttons change renderer, theme, pause/resume and restart. This is an original fictional coastline/territory drawing with broad flat regions, a grid and large display type, not real geography or territorial-control data. All example materials are original procedural CC0 under the existing [dedication](../LICENSE.txt).

**Braille (pixel-raster), single-colour amber Amber Glow and multi-colour phosphor Old Monitor: APPROVED SCOPED.** Use for 2D maps/territory outlines, line graphics, large display type, flat/few-tone graphics and simple geometric 3D (torus, cube, sphere-like primitives). Complex 3D assemblies with fine panels, photos, textured/fine relief and small text are outside scope. This example demonstrates an original 2D source. Braille draws a Unicode-Braille-style dot lattice graphically, not text glyphs or literal ASCII. The source type is locally rasterized system sans.

Amber has real two-radius phosphor glow and stays single-colour amber with no colour control. Old Monitor uses horizontal beam segments, colour-matched bloom/halo and static scanlines; its default is green, with Green/Warm/Cool buttons and a labelled native custom-colour input. Both always present on a dark screen panel in either UI theme. The old glyph-based Monitor is superseded/rejected. Old Monitor colour is a renderer parameter; the UI keeps existing tokens unchanged.

## Raster, motion and finishing

The [canonical decision table and numeric contract](../../../references/ascii-motion.md#canonical-scoped-raster-and-phosphor-contract) own source limits, lattice, hysteresis, residence, cadence, glow radii/alphas, phosphor presets/colour values, minimum custom-colour contrast, scanline opacity and forbidden looks. This is the single parameter owner; consult it for values and colour-selection precedence. `signalStudy.setOptions({phosphor: '#RRGGBB'})` changes colour without resetting phase or residence history; an initial `--itm-phosphor` on `#study` is also supported. Invalid input visibly falls back to default green; low-contrast custom colours warn but remain usable. Cached glow-dot sprites rebuild only when colour/geometry changes and avoid frame-sized blur. A sustained slow display-callback window disables the wide halo with an explicit status; `signalStudy.setWideHalo(false/true)` selects the fallback or retries full glow. A fallback is not full-glow visual parity.

The seamless source period is 12 s. Restart clears history; deterministic capture warms two cycles. Raster width follows CSS width rounded down to the lattice pitch, up to 720; height 480, with no CSS shrinking. The full `SECTOR 07` stays visible at 390 as well as wide widths; type cap height stays within the approved large-type scope.

Pause freezes phase; restart resets even while paused/reduced. Reduced motion shows the static zero pose, including dynamic preference changes. Hidden document, offscreen intersection and page suspension stop the single scheduler. Call `signalStudy.destroy()` on host unmount to release callbacks, observers, listeners, raster arrays and glow caches. Page exit cleans up automatically; persisted page-cache entries suspend/resume. `signalStudy.seek(seconds, resetHistory)` pauses for deterministic sequential inspection; `metrics` exposes display-callback FPS separately from state cadence and render cost. Offline browser evidence does not establish native or physical-display acceptance.

## Native guidance (not tested ports)

**Tk Canvas:** rasterize the original flat outline/type to an existing local pixel surface, sample areas per the canonical contract, retain `on`/`age` arrays and update pooled dot/beam drawing items following the canonical geometry. Own one `after` callback at the approved state cadence; cancel it on unmap/inactive/reduced/close. Use native preference/visibility events. Tk antialiasing and thousands of item updates need native performance and visual verification. If bounded native bloom is unavailable, offer plain Braille or a static pose, explicitly labelled; do not claim phosphor parity.

**WinUI:** use an existing native bitmap/custom drawing surface, pooled dots, theme token endpoints and the same luminance/Bayer/Schmitt/residence rules. Apply cached phosphor sprites only where an existing native surface supports them; otherwise use plain Braille/static. Stop its dispatcher timer on hidden/inactive/reduced/unmount and unsubscribe handlers. Do not add a WebView or graphics dependency for this study. Neither native port, physical OS behavior nor native pixel parity is verified by browser evidence. Existing [Tk](../tkinter_example.py) / [WinUI](../LivingAsciiWindow.cs) text examples are distinct character-art fallbacks, not reproductions of this raster.

Wide-screen layout uses an explanatory/control region beside the unchanged bounded raster at 1920/2560. The 1440 canvas geometry and pixels are retained; larger working space does not imply enlarging the raster lattice.
