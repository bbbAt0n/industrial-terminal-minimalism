# Accessibility implementation guidance

Target WCAG 2.2 AA for web work. Native UI must use its platform's semantic controls, accessibility APIs, scaling, keyboard, and motion settings. This document is an implementation baseline, not a certification.

- Normal text and metadata: contrast at least 4.5:1. Large text may use 3:1 where the WCAG definition applies, but this bundle tests all routine text pairs at 4.5:1. Essential boundaries and state indicators require 3:1 against adjacent backgrounds. Decorative separators are exempt and must not carry essential affordances. Sources: [text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).
- Token contracts cover opaque pairs on both supported surfaces and inverted selection. When composing alpha overlays, images, charts, selected errors, or additional surfaces, measure the actual rendered combination. Do not assume an accent seed is accessible merely because it appears in the palette.
- Status must use words; red/blue/amber is supplemental. Use a visible current marker or inversion plus native current/selected semantics. Validation errors identify the field and how to repair it.
- Keyboard: logical tab order, visible focus, no trap outside modal dialogs, focus return after closing a dialog, accessible names for controls. Keep focus styling under hover/selected/error states. Do not emulate buttons with plain clickable divs.
- Prefer native controls. Use labels, associated hint/error text, `aria-invalid` on invalid fields, and polite live regions for task completion. Do not announce decorative frames or every decorative progress step.
- At 200% text zoom and 400% browser zoom, reflow should preserve content and operation. Test at 320 CSS px and with long localized labels. Preserve logical DOM order; do not use CSS visual order to rearrange keyboard meaning. Sources: [reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [target size minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
- Standard hit targets are at least 44px tall. Dense desktop exceptions must still meet the 24×24px AA criterion or a permitted spacing exception, and should not be used for touch-first controls.
- Reduced motion stops decorative effects without stopping real work. Continuous decorative motion is allowed with a persistent pause/stop/hide control. For automatic moving/blinking/scrolling information lasting over five seconds alongside other content, WCAG 2.2.2 requires a control unless essential; auto-updating information has a separate rule without that duration exception. Reduced motion does not replace the control. Preserve a static equivalent and avoid flashes. Verify real task feedback independently using [motion QA](../execution/motion-qa.md). Source: [pause, stop, hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html).
- In forced-colors mode preserve system colors, borders, selection labels, and focus. Do not force palette values with `forced-color-adjust: none`. Native platform tooltips or placeholder text cannot replace visible labels.
- Use an actual screen reader on the target platform to check navigation landmarks, table headers, form errors, selection and dialog announcements. Automated DOM/contrast tests cannot establish this outcome.
