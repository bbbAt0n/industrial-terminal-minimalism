# Annotated decisions, not page recipes

Use these small contrasts to understand decisions. They supply no full-page composition or required sequence.

**Type roles:** A navigation item, field label, and operation message all address the user in ordinary language. Assign them coherent reading roles. A job ID can use the technical mono role, and a short display statement can use the identity face. The distinction follows meaning. Arbitrarily using mono for one field label and sans for its sibling creates inconsistency even if both fonts are individually approved.

**Density and space:** A dense repeated comparison task can put aligned data close together while preserving readable text and input targets. An unfamiliar decision can need explanatory copy and more breathing room. Copying the same panel padding or region proportions into both ignores their purpose. Both should have perceptible within/between-group spacing relationships.

**Feedback and motion:** Immediate visible state is the functional requirement. A stepped companion can improve continuity or confirm ongoing work without delaying that state. Removing the useful companion solely because a screenshot cannot prove its quality evades the review; use temporal evidence instead. Adding it to a trivial label with no state change adds noise.

Apply the [patterns](../../patterns/README.md) and [review dimensions](../../validation/rubric.md) to the real problem. A valid decision must survive actual content and interactions, not just these short examples.
